YOLO 引导的 SAM3-LoRA 积水分割工程流程总结

本文档总结当前工程从 YOLO 基线、Base SAM3 提示优化、Proposal 选择器， 到 SAM3-LoRA 微调与最终验证的完整工作流。当前原则是：生产默认保持 YOLO-only， 只有当 LoRA + selector 在验证集和最终封存 test 上同时满足精度约束时，才考虑启用。

项目：water_segment 日期：2026-06-30 设备目标：RTX 3060 12GB Test 集：最终冻结前封存

1. 项目目标与核心策略

原始问题是：直接用 Base SAM3 替换或扩张 YOLO 结果时，召回率可能提升， 但 precision 容易下降，导致整体 IoU 不稳定。因此工程路线从“直接微调 SAM3” 调整为更稳的两层结构：

A
YOLO 作为稳定主模型
YOLO 先给出基础 mask，任何 SAM3/LoRA 结果都不能无约束覆盖 YOLO。
B
SAM3 只提供候选 proposal
Base SAM3 或 SAM3-LoRA 生成 text+box、points、global 等候选，不直接作为最终输出。
C
Selector 学习是否采用 proposal
选择器根据 overlap、coverage、growth、distance、score 等特征判断候选是否真的比 YOLO 好。
D
安全回退到 YOLO
只要 selector、adapter 或 SAM3 worker 异常，最终仍保留 YOLO，避免生产路径被破坏。

2. 总体流水线

  ↓

  ↓

  ↓

5. 数据划分与封存原则

Split 用途 约束
Train LoRA 训练、selector 训练、proposal 缓存 使用 FloodNet 训练原图与多尺度 crops。
Val 阈值选择、epoch 选择、模型选择 只用于选择配置，不作为最终 test。
Test 最终冻结后只运行一次 当前阶段完全封存，不进入训练、缓存、阈值选择。

所有 split 按 source_stem 校验，禁止同一原图衍生 crop 跨集合泄漏。

6. Base SAM3 阶段做了什么

  1. 把原来的单一 sam3_conservative 改为 sam3_mode: conservative | balanced | open。
  2. 增加局部提示：YOLO 连通域扩展 box、内部正点、外部负点。
  3. 将 text+box 与 interactive points 作为两个独立 proposal 分支。
  4. 增加受控 global proposal，用于 balanced/open 模式下恢复 YOLO 漏检区域。
  5. 重构 Fusion，显式计算 score、overlap、coverage、growth、distance、面积占比等特征。
  6. 记录失败案例与拒绝原因，为 LoRA 和 selector 提供训练数据依据。

7. Proposal Selector 的作用

Selector 是一个轻量 Logistic Regression，不依赖 pickle，而是导出纯 JSON。 它的核心作用是：判断一个 SAM3/SAM3-LoRA proposal 是否值得替换或补充 YOLO。

输入特征

score
area_ratio
overlap
coverage
iou
area_growth
distance_ratio
candidate_area_ratio
yolo_area_ratio
yolo_confidence
is_text_box
is_interactive_points
is_global_text

决策原则

  • 预测收益不足阈值时，保留 YOLO。
  • 不确定时，保留 YOLO。
  • adapter 或 selector 加载失败时，回退 Base SAM3 或 YOLO。
  • Base SAM3 失败时，整图回退 YOLO。

8. SAM3-LoRA 微调方案

LoRA 不修改基础 checkpoint，也不进行全量微调。当前实现为 Q/V-only LoRA： 包装 SAM3 视觉编码器中的 fused qkv 线性层，只对 Q 和 V 输出切片添加低秩增量。

9. 当前正在运行的步骤

当前正在执行 LoRA proposal cache。这一步会对 1728 个 train/val 样本逐一生成 LoRA proposals， 并把每个 proposal 的 mask、特征、真实 delta_iou 写入 JSONL。 

python scripts/16_cache_sam3_proposals.py \
  --manifest data/sam3_finetune/manifest_train_val.jsonl \
  --config configs/onnx_platform_sam3_lora_trial.yaml \
  --output data/sam3_finetune/lora_proposals.jsonl \
  --cache-dir data/sam3_finetune/lora_cache \
  --resume
已修复缓存脚本：现在每处理完一个样本就流式写入 JSONL 和 summary。 即使中途中断，也可以通过 --resume 继续，不会丢掉已有 proposal 行。

10. 最终验收标准

指标 门槛 意义
Test Precision 不低于 0.8124 - 0.01 precision 优先，避免误报扩张。
Test IoU 高于 YOLO-only 0.6645 必须带来整体有效提升。
Small-object recall 不低于 0.6066，且优于 Base SAM3 验证小水体恢复能力。
FP 图片数 不超过 YOLO-only 的 4 张 控制误报图片数量。
FN 图片数 不超过 3 张 控制漏检。
显存 峰值低于 10GB，无 OOM 保证 RTX 3060 12GB 可运行。
如果 LoRA + selector 没有达到全部门槛，则不启用 adapter， 生产继续使用 YOLO-only。Open 模式只用于失败挖掘，不作为生产默认。
